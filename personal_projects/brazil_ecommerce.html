Brazilian E-Commerce Database Design & Insight Development

BANA 279 · Business Data Management · UC Irvine, Paul Merage School of Business

SQL Relational Database Design ER Modeling 3NF Normalization

Presentation

Overview

Designed and implemented a relational database system for a multi-vendor e-commerce platform using the Olist Brazilian E-Commerce dataset — 100k+ real-world orders spanning sellers, customers, and products. The project addressed real operational challenges in large-scale e-commerce environments: inconsistent delivery performance, seller reliability variance, and fluctuating customer satisfaction. The solution was a structured, normalized data management platform capable of supporting business intelligence and operational decision-making.

Database Design

The schema was built around six core entities — Customer, Seller, Order, Order Item, Product, and Review — with supporting zip code tables for geographic normalization. Each entity was documented with full metadata before modeling began.

The design process followed a rigorous normalization workflow:

  • Mapped an Entity-Relationship (ER) diagram capturing all relationships and cardinalities across the schema
  • Conducted as-is dependency analysis to identify functional dependencies and redundancies in the raw dataset
  • Normalized all tables to Third Normal Form (3NF), eliminating transitive dependencies and ensuring data integrity across the relational structure

SQL Query Development

Developed 10 business-driven SQL queries targeting key operational and strategic use cases:

Query Business Application
Most Valuable Sellers Identify top performers for incentives and partnership strategy
Top Revenue Categories Prioritize product categories for promotion and inventory investment
Regional Demand Analysis Pinpoint highest-demand geographic markets for targeted marketing
Seller Satisfaction Scores Rank sellers by customer review data for quality control decisions
Seasonal Order Trends Surface demand patterns to support inventory planning and staffing
High-Value Customers Identify top spenders to power loyalty and CRM programs
Seller Performance Benchmarking Separate exceptional sellers from average using dynamic benchmarks
Low-Satisfaction Order Flagging Surface problematic orders to investigate root causes of dissatisfaction
Category-Level Satisfaction Connect customer ratings to product categories to guide quality improvement
High Average Order Value Categories Distinguish volume-driven vs. value-driven categories for pricing strategy

Key Takeaways

Clean database design directly enables analytical capability — normalized schemas make complex queries faster and easier to maintain. High-revenue categories don't always have high satisfaction scores, a nuance that only surfaces when the schema supports cross-dimensional queries.

Scope for extension identified during the project included adding Returns/Refunds, Marketing Campaign, and Inventory entities, as well as strengthening data validation constraints and standardization pipelines for production readiness.
