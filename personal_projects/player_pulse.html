Player Pulse

Valorant Customer Spend Analysis — Personal Project

Python SQL Machine Learning EDA Tableau

Overview

Player Pulse is a multi-stage lifecycle segmentation and spend prediction framework built on synthetic Valorant-style player data. The project simulates 109,000 players across five seasons (2021–2025) — spanning 500,000+ transactions — and works through a full analytics pipeline: SQL exploration, RFM segmentation, Random Forest modeling, and Tableau visualization. The goal is to surface actionable monetization and retention insights for a live-service game context.

Data Generation

Both datasets were synthetically generated using generate_datasets.py, designed to reflect realistic behavioral and spending patterns in a live-service game:

  • Transaction data — ~500,500 rows; each record represents a single in-game purchase with a user ID, transaction date, and amount
  • Player behavior data — 109,000 rows; one record per active user-season, tracking rank, session depth, esports viewership, agent diversity, cross-platform hours, and 30-day retention

Players were assigned to four spend tiers at generation time: Non-Spender (40%), Casual (35%), Mid-Tier (20%), and Whale (5%). Rank progression, retention rates, and seasonal revenue weighting (35% concentrated in Sept–Dec) were all baked into the synthetic parameters to mirror real live-service dynamics.

Pipeline

Step 1 — SQL Exploratory Analysis

Before any modeling, a correlation heatmap surfaced five business questions worth investigating in SQL. Each query was designed to test a specific signal from the heatmap:

Question Finding
Does early spending predict future retention? Players who spent in a prior season were 11.4 percentage points more likely to be retained
Do esports watchers spend more than non-watchers? Esports watchers spend more in aggregate — but controlling for longevity (spend per season), the gap narrows, revealing longevity as the confounding factor
Does agent diversity predict long-term engagement? Players who experiment with more agents show higher season counts and retention rates — experimentation is a leading indicator of stickiness
Who are the at-risk high-value players? Recency-bucketed spend analysis surfaces lapsing and at-risk players by revenue at stake, enabling prioritized re-engagement targeting
Does rank + session depth together predict spend better than either alone? High-rank, long-session players outspend all other combinations — the interaction effect is stronger than either variable individually

Step 2 — RFM Segmentation (Python)

Using the transaction data, each player was scored on Recency (days since last purchase), Frequency (transaction count), and Monetary (total spend) — each on a 1–5 quintile scale. RFM composite scores mapped players into eight named business segments:

  • Champion — recent, frequent, high-spend
  • Loyal Player — consistent across all three dimensions
  • High Spender — recent with large purchase amounts
  • New Player — recent but low frequency
  • At Risk — previously frequent/high-spend but lapsing
  • Lapsing — declining engagement, moderate spend history
  • Churned — very low recency score
  • Casual / Non-Spender — minimal or zero transaction history

The merged behavioral + RFM dataset was exported as player_segments.csv for downstream modeling and visualization.

Step 3 — Random Forest Models (Python)

Two separate models were built on the aggregated 109,000-player dataset, using only behavioral features to prevent data leakage (spend-derived columns like transaction count and recency days were excluded from model inputs):

Model Question Target Evaluation
Classifier Will a player spend at all? is_spender (binary) ROC-AUC, classification report; class_weight='balanced' to correct for the ~40% spender rate
Regressor For players who do spend, how much? total_spend (spenders only, ~65k players) MAE, RMSE, R²; trained on spender subset only

Both models share the same 13 behavioral input features: cohort year, seasons active, average and peak rank score, session depth, esports viewership, agent diversity, cross-platform engagement, account age, and average retention. Feature importances were exported to feature_importance_comparison.csv for cross-model comparison.

Step 4 — Tableau Dashboard

A Tableau workbook (WIP_Dashboard.twb) is in progress, visualizing segment distributions, revenue breakdowns, and retention metrics across the lifecycle model. The dashboard will serve as the primary deliverable for presenting findings to a non-technical audience.
